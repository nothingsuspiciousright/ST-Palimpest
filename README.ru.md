PALIMPEST 1.0.4 — самостоятельное расширение SillyTavern

Установка
1. Сохраните важные чаты и экспортируйте старый Memory Book. Если установлена версия модифицированного Summarize, сохраните оригинальную папку memory, затем восстановите штатный Summarize при возможности.
2. Распакуйте папку Palimpest из архива в SillyTavern/public/scripts/extensions/third-party/ (или в каталог пользовательских расширений ST, например data/default-user/extensions/). Внутри Palimpest должны лежать manifest.json, index.js, settings.html и style.css.
3. В Manage Extensions отключите встроенный Summarize (memory) и перезагрузите страницу. Не запускайте одновременно два менеджера памяти: иначе память может дублироваться в RP-контексте. Не удаляйте старые данные из чата.
4. Откройте Palimpest в меню Extensions. При первом запуске он импортирует прежние настройки Summary Prompt, инъекции, микропресеты, и переносит существующий архив предыдущей версии без изменения содержимого. Если архива нет, импортирует сохранившиеся message.extra.memory. Вставьте собственный скелет Memory Book в Summary Prompt, если он не был импортирован. В комплекте нет готового промпта или скелета: при чистой установке без импорта поле пустое. Существующие локальные промпты сохраняются. Очистка поля не изменяет активную память, архивы или снимки черновиков.

Подключения
- New preset: название, HTTPS API base URL (OpenAI-compatible), API key, точный Model ID, Max output tokens. Test отправляет короткое тестовое сообщение без истории. Можно использовать разные модели между частями генерации.
- Сохранённые ST Connection Profiles (Chat Completion) тоже поддерживаются через независимый ConnectionManagerRequestService с includePreset:false / includeInstruct:false. Основной профиль не переключается. Current saved ST profile требует выбранного и сохранённого профиля. Без профиля или микропресета запрос не отправляется. Текстовые completion-профили не поддерживаются.
- Ключи не хранятся в настройках или экспортируемом архиве. Remember key in this browser хранит ключ в localStorage без шифрования; иначе ключ живёт до перезагрузки. Используйте доверенный сервер, браузер и прокси. Запрос идёт через сервер ST; сервер и прокси могут иметь собственное логирование.

Изолированный контекст
- Summary Prompt (скелет) является единственным специально сформированным system message. Отдельное сообщение содержит текстовую историю (включая последний пост, только выбранные свайпы), карточки персонажей (описание, характер, сценарий, примеры, character note), персону, Author's Note, активированные World Info и активный Memory Book как справочные данные.
- World Info выбирается штатным dry-run сканером ST с текущими параметрами активации и бюджета WI; включены доступные позиции before/after, depth, AN, examples, outlets. Это НЕ автоматическая отправка всех неактивных лорбуков. Author's Note берётся из метаданных, включая поддерживаемое переопределение на персонажа. Если какая-то из этих секций пуста, в отчёте отображается 0 символов.
- RP Prompt Manager не вызывается, его инструкции и пост-история не добавляются. Текст, который уже физически записан в персоне, карточке, AN, WI или самом сообщении, остаётся частью исходных данных. Не включаются вложения, удалённые сообщения, альтернативные свайпы, системные сообщения и архивы версий. Контекст не режется автоматически; лимит модели сохраняется.

Продолжение и защита памяти
- Summarize now создаёт отдельный черновик. Перед запросом сохраняется снимок исходного контекста и оригинального Summary Prompt. Старый активный Memory Book не меняется.
- Continue from cutoff доступна для черновика, в том числе после нормального stop, если модель всё же пропустила конец. Посылает тот же снимок, весь накопленный черновик и команду дописать только недостающий суффикс. Дословный перекрывающийся текст удаляется при склейке, существующий префикс не переписывается. Гарантии, что модель не повторит смысл или не ошибётся на границе, нет: проверяйте черновик перед Apply.
- При стриминге входящие символы периодически записываются в метаданные чата (примерно каждые 12 секунд при получении данных). Stop & keep draft прерывает запрос. При сетевом сбое сохраняется уже полученный текст, если он доступен. После перезагрузки последний сохранённый checkpoint восстанавливается. Если сервер не передал ни одного фрагмента или вкладка закрыта до checkpoint, неполученные/несохранённые символы восстановить невозможно. На старом черновике без снимка программа предлагает собрать источник заново из текущего чата и текущего скелета.
- При использовании ST Connection Profiles поток штатного сервиса не выдаёт finish_reason/usage, поэтому показан unknown; при микропресетах сведения сохраняются, если прокси их передаёт. Некоторые прокси не поддерживают streaming или особые форматы событий. Проверяйте на копии чата.
- History: предыдущие черновики, активные версии и восстановленные версии. Apply и Restore создают новые записи; Discard оставляет ранее сохранённый черновик. Backup now делает копию активной памяти. TXT и JSON доступны для экспорта. В JSON-экспорте нет снимка исходного контекста незавершённой задачи; он остаётся в файле чата. Снимок удаляется после Apply/Discard. История версий хранится вместе с чатом; удаление чата удаляет архив. Архив и временный снимок увеличивают размер файла, но не инъецируются в RP-контекст.
- Не переключайте чат во время генерации. При смене чата запрос останавливается; сохраняются уже записанные checkpoints. Если исходный чат изменился, при Apply появляется подтверждение. Несохранённые ручные правки нужно сохранить кнопкой Save changes / Save draft edits.
- {{summary}} и {{palimpest}} зарегистрированы для совместимости, но при включённом штатном Summarize может возникнуть конфликт; отключите его. Если используете макрос вручную в пресете, выставьте Injection Position = None, чтобы не удваивать память.

Проверено: синтаксис JS; изолированные тесты импорта, сборки источников, оригинального скелета, дописывания, склейки, восстановления checkpoint, формирования API payload, потокового ответа и обрыва SSE. Живой ST, UI и реальные провайдеры не тестировались. Целевые API сверены с исходниками staging ST; возможны отличия в конкретной версии.

Происхождение: производная от предоставленного встроенного Summarize SillyTavern и предыдущих модификаций, с сохранением авторства исходной разработки. https://github.com/SillyTavern/SillyTavern
